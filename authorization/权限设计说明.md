# 权限层设计说明

## 定位

权限层是固定的系统控制，不由大模型判断。它决定某个用户能够查看哪些字段、读取哪些证据、生成哪些报告以及执行哪些人工操作。权限过滤必须发生在页面展示、证据检索和模型上下文拼装之前。

当前项目尚未接入登录、角色识别和运行时字段过滤；本文件是后续实施时的唯一业务口径，不代表已有权限功能已生效。

## 初始角色边界

| 角色 | 可查看范围 | 可执行范围 |
|---|---|---|
| 普通客户经理 | 企业基本信息、产品商业化、公开经营与已授权的审批结论 | 发起资料补充、查看本人可见报告 |
| 审批人员 | 完整审批方向、排名依据、行业对比和必要的企业画像 | 审核、确认补件和形成审批意见 |
| 风险合规人员 | 风险事项、治理团队、关联关系、证据链和全部审批材料 | 复核风险、调整复核结论、发起持续监测 |
| 系统管理员 | 系统配置和审计日志；不因管理员身份自动取得业务数据查看权 | 管理角色、字段策略和运行记录 |

“人员结构、控制权、客户供应商明细、未公开融资条款”等敏感字段，应由字段策略逐项配置；默认不向普通客户经理展示，也不传入其发起的模型任务。

## 后续实施规则

1. 为每个字段组建立 `allow_roles`，默认拒绝未声明角色。
2. 按用户角色过滤结构化事实和证据，再生成模型上下文；禁止仅在模型输出后做遮盖。
3. 对导出、重新运行模型、修改人工结论等操作单独授权并记录审计日志。
4. 模型不得根据自然语言指令提升数据范围或操作权限。
