# 权限管控实现手册

## 1. 目标

在不改变企业画像、行业画像和授信审批主流程的前提下，为当前 Streamlit 界面增加最小可用的权限控制：

1. 前端首次进入时选择当前使用身份；
2. 一般业务人员仍可调用 DeepSeek 生成报告，但只能运行被授权的分析方向；
3. 高级业务人员可以查看敏感字段、查看完整证据，并维护允许业务人员使用的提示词和规则；
4. 程序员或系统管理员不作为普通业务界面的身份选项；
5. 后续接入登录系统时，只替换身份来源，不重写权限判断。

本阶段是应用层权限和界面权限实现，不是完整的登录、组织架构和安全认证系统。当前身份选择器用于演示和联调，不能替代正式登录鉴权。

## 2. 身份定义

系统只在普通界面暴露两种身份：

- `general_business`：一般业务人员；
- `senior_business`：高级业务人员。

开发人员、系统管理员和数据库管理员属于部署或运维身份，不进入普通业务身份选择器。本阶段不实现这些身份的前端工作区。

## 3. 权限对象和动作

权限配置文件放在 `authorization/权限规则.yaml`，不属于模型提示词，也不传给 DeepSeek。

权限对象分为四类：

- 页面：材料管理、企业画像、行业背景、客户风险评级报告；
- 数据：普通画像事实、敏感画像字段、完整证据、原始结构化 JSON、模型调试信息；
- 模型动作：企业画像生成、行业画像生成、主题分析、分方向审批报告、排名和综合评级；
- 配置动作：查看业务提示词、修改业务提示词、修改本体接口和程序代码。

每个权限对象使用 `view`、`run`、`edit` 三类动作。普通业务人员不能修改业务提示词，但仍可对授权方向执行 `run`。

## 4. 初版权限边界

### 4.1 一般业务人员

允许：

- 查看企业画像、行业画像和已生成的客户风险评级报告；
- 查看非敏感事实和报告中的证据摘要；
- 调用大模型生成被授权的企业画像主题分析、行业画像和授信报告；
- 查看生成结果和信息缺口。

限制：

- 不查看人员构成、教育背景、职业背景等敏感字段；
- 不查看完整原始证据和调试 JSON；
- 不修改任何提示词、字段语义或业务规则；
- 不运行未授权的方向；
- 不审批或发布正式结果，初版只控制生成和查看。

### 4.2 高级业务人员

允许：

- 查看全部画像字段和完整证据；
- 运行全部已配置的企业、行业和授信分析方向；
- 修改白名单内的业务提示词、字段语义和抽取规则；
- 查看分析过程、信息缺口和结构化结果。

仍然限制：

- 不通过业务配置文件修改字段 ID、字段类型、对象 ID、关系 ID、domain/range 或数据库接口；
- 不直接修改 Python 程序和数据库结构。

## 5. 数据过滤边界

权限过滤必须同时作用于三个位置：

1. 页面展示：不向一般业务人员展示敏感字段和调试区；
2. 模型输入：生成报告前过滤未授权字段，避免模型输出中间接泄露敏感信息；
3. 服务动作：服务函数再次检查当前身份是否可以执行该分析方向或编辑提示词。

普通业务人员看到的是过滤后的画像和报告，不是先取得全部数据后仅用 CSS 隐藏内容。

## 6. 业务提示词白名单

高级业务人员只允许修改业务可维护文件：

- `prompts/data/企业画像字段语义.yaml`；
- `prompts/data/企业画像抽取规则.yaml`；
- 后续明确列入白名单的业务规则文件。

以下内容不开放业务编辑：

- `prompts/data/企业画像本体.yaml`；
- Python 源代码；
- 数据库结构和迁移脚本；
- 关系对象接口和字段类型定义。

## 7. 实现步骤

1. 新增 `authorization/权限规则.yaml`，集中定义身份、可见字段、可运行方向和可编辑提示词白名单；
2. 新增 Python 权限服务，提供当前身份、字段可见性、页面权限、方向运行权限和提示词编辑权限判断；
3. 在 `v5_app.py` 的最前端增加身份选择器，并将身份保存到 `st.session_state`；
4. 在企业画像、行业背景和审批报告页面中隐藏未授权操作和敏感内容；
5. 在传给模型的企业画像和报告输入中应用同一字段过滤；
6. 仅向高级业务人员开放业务提示词查看或编辑入口；
7. 为权限服务、配置读取和页面分支增加单元测试；
8. 运行现有完整测试，确认不影响无权限上下文下的原有服务调用。

## 8. 后续登录系统接入

正式登录系统接入后，身份选择器改为读取登录会话中的角色。权限配置、字段过滤和服务层判断保持不变。
