# 提示词接口化重构手册

## 1. 目标

让每一个当前业务接口都有一个唯一的、真正参与模型调用的 Markdown 提示词文件。Markdown 是业务规则的维护入口；Python 只负责读取章节、注入运行时数据、调用模型和进行确定性校验。

本次不按历史版本或代码模块拆文件，也不把同一功能的规则分散在“镜像提示词”和 Python 字符串中。

## 2. 当前主流程接口与唯一提示词

| 业务接口 | 模型阶段 | 唯一提示词 |
|---|---|---|
| 企业画像调查与候选生成 | 数据层：固定目录选择、ReAct 调查、结构化事实抽取、关系核验和格式修复 | `prompts/data/企业画像数据规则.md` |
| 行业背景画像 | 数据层：ReAct 证据调查、洞察生成、语义审核 | `prompts/data/行业背景数据规则.md` |
| 企业画像主题分析 | 逻辑层：读取主题事实、生成六大维度分析 | `prompts/logic/企业画像逻辑规则.md` |
| 客户风险评级报告 | 逻辑层：单方向审批点判断、同方向排名、九级客户风险评级和格式修复 | `prompts/logic/授信审批逻辑规则.md` |

行动建议规则单独放在 `prompts/action/行动建议规则.md`，作为业务人员维护的行动层文件；当前没有对应模型接口，由 Python 和人工流程使用。权限规则放在 `authorization/`，不是模型提示词，也不由模型决定。

## 3. 文件内部章节

同一业务接口的不同模型阶段集中在同一文件中，用二级标题区分。代码按章节读取，不把整份说明书重复发送给模型。

```text
prompts/
  data/
    企业画像数据规则.md
    行业背景数据规则.md
  logic/
    企业画像逻辑规则.md
    授信审批逻辑规则.md
  action/
    行动建议规则.md
  提示词目录说明.md
```

## 4. 代码约束

1. 所有当前主流程的模型调用必须通过 `load_prompt_section` 或 `render_prompt_section` 读取上述四个文件。
2. 运行时数据只能作为占位符或用户消息注入，不能把企业事实、证据、审批点和排名数据固化进 Markdown。
3. Python 保留字段白名单、JSON Schema、证据引用、审批方向覆盖、九级评级边界和调用上限校验。
4. 业务规则不得在 Python 中再写一份与 Markdown 等价的自然语言版本；确需技术格式说明时，只保留结构和变量拼装。
5. 当前已删除旧高级功能及其专属提示词，主流程目录不再保留兼容副本。

## 5. 实施步骤

1. 建立四个主提示词文件，合并现有有效规则并去掉历史说明、重复代码块和失效链接。
2. 将企业、行业、画像分析、审批报告相关函数改为按章节读取唯一文件。
3. 将综合评级从旧的独立文件迁入 `prompts/logic/授信审批逻辑规则.md` 的综合评级章节。
4. 删除不再属于当前四个工作区的旧提示词、隐藏服务和专属脚本。
5. 更新提示词索引，标明每个章节对应的 Python 接口。
6. 搜索主流程是否还引用旧文件名或隐藏自然语言规则，并执行完整现行测试。

## 6. 验收标准

- 修改四个主提示词文件中的规则后，对应 `build_*_messages` 的 system prompt 会改变；
- 主流程目录不再出现 `01` 至 `09`、V1 或“金融风险案例”等历史文件名；
- 四个业务接口的运行时提示词均可通过文件路径追溯；
- 结构校验和数据库行为不因提示词迁移改变。
