# 科技型企业风险辅助审查系统——当前技术说明

## 1. 文档定位

本文档只说明当前有效的系统结构、数据流和代码边界。客户风险评级报告的详细需求、审批点配置、输入上限、排名规则和实施步骤，以《[授信审批报告生成工作手册](../business/授信审批报告生成工作手册.md)》和《[客户风险评级报告改造手册](客户风险评级报告改造手册.md)》为准。

本文档不记录历史测试过程、旧版本切片、模型调参过程或单个企业的临时修补。

## 2. 系统目标

系统读取当前企业材料和行业研究报告，形成可追溯、可审核的客户风险评级报告；同行企业年报可作为可选的相对比较增强输入。

最终输出按风险评级指引的方向组织。每个方向包含一句话总结和固定审批点；每个审批点说明企业现状、行业基准、可选同行位置、判断、证据和信息缺口。所有方向汇总后，生成一个业务人员能够直接阅读的核心风险判断、缓释因素、判断边界和后续行动建议。

企业画像的十个领域是事实输入维度，不是最终报告目录；行业背景的八个维度是环境基准，不直接替代企业事实。

## 3. 主流程

```text
企业 PDF / 行业研报 /（可选）同行年报
              ↓
        SourceAsset + EvidenceUnit
              ↓
    企业画像、行业背景画像（人工批准）
              ↓
       单企业方向上下文组装
          （企业 + 行业）
              ↓
       大模型生成单企业方向报告
              ↓
        Python 结构和证据校验
              ↓
          人工批准方向报告
              ↓
        （可选）同行样本比较卡
              ↓
        （可选）大模型形成方向排名
              ↓
      （可选）Python 校验排名并计算名次分
              ↓
     大模型汇总已批准方向报告和可用排名
              ↓
          综合核心风险判断
              ↓
              人工批准和导出
```

每个风险评级方向单独调用一次报告模型；只有选择同行增强模式时，才对多家企业的同一方向调用横向排名模型。单个审批点只接收配置允许的少量企业事实、行业要点和指标，避免把整份年报直接塞给模型。

行业背景画像的 ReAct 调查默认先搜索八个维度，并允许对不足维度补充检索；最多读取 36 条正文、调用读取工具 10 次，每次目录最多返回 16 项。提取和审核使用 24,000 token 的 thinking 输出上限，提取阶段每个维度最多保留 4 条独立要点。读取和提取顺序优先覆盖不同维度、材料来源和章节；最终画像仍只引用已读取的原文证据。

## 4. 代码结构

### 4.1 材料与画像

- `src/ingestion/`：导入 PDF、HTML 并切分为证据单元；
- `src/profiles/`：企业画像候选、受控 ReAct 调查、证据引用和人工审核；
- `src/industry/`：行业背景画像、行业证据和人工审核；
- `src/ontology/`：加载、注册和校验 Ontology；运行时数据定义位于 `prompts/data/企业画像本体.yaml`。

### 4.2 授信审批

- `src/approval/models.py`：同行样本、指标、审批点、分方向报告和综合报告模型；
- `src/approval/ranking.py`：数值指标的样本内稠密排名和名次分；
- `src/approval/guideline_definitions.py`：授信指引方向、审批点、允许输入和比较标准；
- `src/approval/guideline_context.py`：按审批点有限组装企业、行业和同行上下文；
- `src/approval/guideline_reporting.py`：单企业分方向报告提示词、输出校验和证据汇总；
- `src/approval/direction_ranking.py`：同方向比较卡、相对排名、并列和不可比校验、方向名次分；
- `src/approval/reporting.py`：综合核心风险判断及 Markdown 导出；
- `src/approval/repository.py`：SQLite 对象保存、读取和审核状态流转。

### 4.3 页面与脚本

- `v5_app.py`：Streamlit 工作台。授信工作区的“授信指引报告”页签提供分方向报告、方向排名和人工批准入口；
- `src/ui/v5_services.py`：页面服务层，负责加载已批准对象、调用审批模块和保存结果；
- `scripts/`：画像、ReAct、报告和测试数据的命令行入口。

## 5. 大模型与 Python 的职责

大模型负责：

- 在已审核、已限量的材料中形成自然语言判断；
- 解释企业事实与行业环境、同行位置的关系；
- 生成审批点判断、一句话总结和综合风险叙述；
- 在同一方向的结构化比较卡上形成相对排序和比较理由。

Python 负责：

- 加载授信指引和字段映射；
- 筛选已批准输入并控制每个审批点的数量；
- 计算数值指标排名和方向名次分；
- 校验模型返回的审批点、引用、排名覆盖、并列和不可比企业；
- 保存审核状态、证据链和报告。

Python 不通过关键词直接生成自然语言审批结论，也不让模型自行计算名次或名次分。

## 6. 审核状态和数据边界

企业画像、行业背景、同行样本、指标值、分方向报告、方向排名和综合报告均有 `pending`、`approved`、`rejected` 状态。

只有已批准对象才能进入下一层正式流程：

- 未批准企业画像不能进入审批上下文；
- 未批准行业画像不能作为正式行业基准；
- 未批准指标值不能参加数值排名；
- 未批准分方向报告不能参加方向排名或综合报告；
- 未批准方向排名不能进入综合报告。

所有报告结论保留到画像项、行业要点、指标值和 `EvidenceUnit` 的引用链。信息不足保留为信息缺口或判断边界，不改写为负面事实。

## 7. 当前实现状态（2026-08-18）

核心链路已经落地，当前代码具备：

1. 11 个授信指引方向、固定审批点、企业字段—行业维度—同行指标映射；
2. 分方向有限上下文、单企业报告、引用校验、待审核/批准状态和 Markdown 导出；
3. 同方向比较卡、模型相对分组、并列与不可比较校验、Python 稠密名次和名次分；
4. 仅使用已批准分方向报告和方向排名生成综合核心风险判断；
5. 企业画像“领域 → 主题 → 支撑事实”阅读层，以及按主题受控 ReAct 的画像分析层；
6. 3200 字符 PDF 切片、同章节连续证据自动补读、`value_scope` 数值口径归并；
7. 客户/供应商双侧抽取、产品字段边界、企业阶段和技术成熟度的通用校验；
8. V5 页面中已保存分方向报告、方向排名的查看、下载与审核入口，以及综合报告的生成和审核入口；
9. `deepseek-v4-flash` 的固定模型配置：事实抽取使用 `sampling`，检索、分析、比较、排名和报告使用 `thinking`；单请求超时为 180 秒；
10. 自动化回归测试已覆盖上述核心规则，真实模型调用与自动化测试相互隔离。

当前真实材料状态：

- 已批准 13 家企业画像和 1 份智能机器人行业背景画像；其中新松机器人已完成企业画像并完成 1 个主题分析维度，其余 12 家已完成六个主题分析维度；
- 正式同行样本 `robotics_2025_core_cohort` 包含 10 家 2025 年可比企业，财务方向的报告和排名已完成正式闭环；
- 独立试验样本 `robotics_2025_assumption_test` 包含 12 家企业。其中哈工智能沿用 2021 年原始事实、赛为智能沿用 2024 年原始事实，仅为流程验证假设为 2025 年；
- 试验样本已生成 11 个方向共 132 份待审核报告，以及 10 个待审核方向排名；“定量评估”按定义不设企业间排名。试验结果不得转为正式授信结论，也不得与正式 10 家样本混用。

## 8. 当前运行边界与后续目标

### 8.1 Streamlit 与工作数据库

V5 默认使用 `data/current_project.db`；侧边栏可切换 SQLite 路径，但切换后只显示所选数据库内容。`.streamlit/config.toml` 已设置 `fileWatcherType = "none"`，避免 Streamlit 扫描 `transformers` 懒加载模块时触发未安装的 `torchvision`。启动命令为：

```powershell
streamlit run v5_app.py
```

关闭源码监视器后，修改 Python 文件需手动刷新或重启页面。系统不要求本地 embedding、向量数据库或 GPU；报告阶段只使用已组装的、有限的画像/行业/同行上下文，不重新把原始 PDF 输入模型。

### 8.2 页面与结果查看

业务主导航固定为材料管理、企业画像、行业背景、客户风险评级报告。企业画像按大领域默认收起；展开后依次显示主题叙述、主题分析、关键记录以及可折叠的原子事实和证据。

主业务页面统一遵循“先选业务对象，再看对应结果”的展示规则。材料管理先选企业；企业画像先选企业画像；行业背景先选行业画像；客户风险评级报告先选企业、报告批次和审批方向。主页面不得在未选择对象时渲染跨企业的全量结果表格，也不得把内部 ID 作为主要阅读入口。

实现步骤：

1. 为每个主业务页面建立可读的对象选择项，显示企业中文名、行业名、报告期或审核状态等必要信息；
2. 选择对象后仅加载其关联材料、画像或报告；
3. 将全量表格替换为摘要计数、可读选择框和按维度/主题的展开内容；
4. 将跨对象查询明确标注为高级或调试功能；
5. 验收时，任一主页面的首次打开不出现混合企业结果，切换对象后页面内容同步切换。

### 8.2.2 审批报告中的排名与证据展示

单个审批点可以同时引用多个可比数值指标，因此会产生多条“样本内指标排名”。每条排名必须显示指标名称、企业数、名次和名次分；不得只显示多个无名称的名次。多个指标排名不等同于多个方向排名，也不构成重复报告。

每个审批点的证据引用必须在正文之后以可折叠区块展示。证据区块仅列出该审批点已引用的原文片段和证据编号，不将证据片段混入企业现状、行业基准或审批判断正文。默认收起，避免正文被大量原文打断。

审批判断正文只能使用业务自然语言，不得向业务人员暴露 `metric_id`、`enterprise_item_id`、`industry_insight_id` 等内部引用标识。内部标识只用于模型输出校验和证据关联；展示层将其替换为独立的证据区块。

实现步骤：

1. 由报告展示层根据同一同行样本读取指标定义，为已保存的排名补充指标名称；
2. 将排名展示为“指标名称：第 x/y 名，名次分 z”；
3. 将审批点原文证据渲染为独立折叠区块；
4. 不改变已保存的审批判断、排名结果和证据引用；
5. 验收时，多指标审批点可区分每条排名的含义，所有方向报告均能查看其已保存证据。

客户风险评级报告页已支持：

1. 在“单企业分析”模式下，只选择企业画像、行业背景和指引方向，生成不绑定同行样本的分方向待审核报告；切换到“同行增强分析”时才选择同行样本；
2. 查看时先选择企业，再按风险评级指引选择一个方向；页面只展示该企业该方向的一份当前报告，并提供下载和审核入口；
3. 在同行增强模式下选择同一方向的同行样本，查看、下载和批准已保存的方向排名；
4. 查看企业时，综合评定与 11 个分方向报告分开呈现；综合评定是企业级结论，不替代任何方向报告；
5. 客户风险评级报告工作区在 11 个方向报告批准后即可生成客户风险评级报告；有已批准排名时作为可选补充。

系统不再提供历史案例、相似案例或高级配置页面；同行样本、指标和审批点配置由当前授信审批工作区读取既有配置。

### 8.2.1 客户风险评级报告查看层级

用户查看已生成结果时，界面必须采用固定层级：

```text
企业
├── 企业综合评定（如已生成）
└── 授信审批指引方向
    ├── 行业市场空间
    ├── 行业竞争格局
    ├── ……
    └── 反洗钱和制裁合规管理要求
```

一家公司存在 11 份分方向报告是系统的正常输出：每份报告只对应一个风险评级方向。单企业模式下每家企业一份；同行增强模式下同一企业还可能因不同同行样本形成不同批次的报告。查看页不得先渲染全部企业、全部方向的报告表格，也不得要求业务人员从混合报告 ID 列表中识别目标报告。用户依次选定企业、报告模式和方向后，仅查询并显示该组合下版本号最高的一份报告。

实现步骤：

1. 从已保存分方向报告中按企业画像和指引方向建立查看索引；
2. 在主页面先提供企业选择，再提供该企业已生成方向的选择；
3. 只渲染所选方向报告的正文、状态和下载入口；
4. 将全量报告表格和原始报告 ID 选择从主查看路径移除；
5. 以同一企业有多份方向报告、同一方向只显示一份当前结果为验收条件。

方向排名的查看页同时展示最终排名和“排名依据”：固定比较标准、样本报告期与入样规则、每家企业实际用于排名的比较卡。比较卡按审批点展示企业现状、行业基准、同行比较、审批判断、关键事实、数值指标名次和信息缺口；排名分组理由与不可比较企业也在同页可见。该展示只读取已保存的分方向报告、排名和已批准画像，不新增模型调用，也不改变排名结果。

所有面向业务人员的企业选择框必须显示企业中文全称，可在名称后附当前/历史画像等中文状态；页面内部仍传递 `profile_id`、`case_id` 等稳定 ID。原始 ID 仅在高级调试区展示，不得作为主流程中选择企业的主要文案。

### 8.3 当前业务材料与数据边界

当前活动材料共 15 份：两份智能机器人行业研报，以及宇树、埃夫特、科沃斯、云深处、乐聚、石头、越疆、深之蓝、天智航、亿嘉和、哈工智能、赛为智能、新松机器人的企业报告。前十一家企业报告为 2025 年材料；哈工智能为 2021 年材料，赛为智能为 2024 年材料。

企业画像必须保留原始报告期、主体、单位和统计范围。哈工智能、赛为智能可参与“假设口径试验样本”的流程验证，但不能进入正式 2025 年数值排名或正式综合审批结论；补齐同期材料并重新审核后才可进入正式样本。

### 8.4 当前实现的画像质量规则

企业画像保留原子事实作为唯一事实底座，阅读层再稳定归并为主题块。主题块按领域、主体、报告期和统计口径组织，不能把交易金额、比例或专利分项孤立展示为企业特征。主题分析只读取该领域的主题事实包；每个有事实的主题都必须被读取，事实较多时分页读取，模型输出只能引用已读取的事实和证据。

数值归并使用 `value_scope` 区分总计、分项、子项和统计范围。不同主体、报告期或口径的值不合并；总分项不一致时保留“需核实”边界。客户与供应商分别发现、抽取和归并；客户、供应商、交易对手或项目不得误写为产品。企业发展阶段必须有原文明确阶段词；技术名称、成熟度等同表关键属性必须成对提取或明确记录缺口。

PDF 默认以 3200 字符切片。读取一个证据单元时，会补读同一来源、同章节、相邻索引的连续单元并计入读取上限，减少跨页表格或长表格被切断导致的事实遗漏。

### 8.5 真实验证与正式验收目标

代码闭环已完成，下一步是把试验结果转化为可审核的正式业务结果，而不是继续扩大 Agent 复杂度：

1. 对 12 家企业的 11 个待审核方向报告和 10 个待审核方向排名做内容验收，重点核查事实、报告期、行业关联、不可比较理由和证据链；
2. 对正式 10 家同期样本，按同一流程补齐其余可排名方向的报告、排名和人工批准；
3. 在同一企业的 11 个分方向报告及相关方向排名均已批准后，生成综合核心风险判断；
4. 检查综合报告是否清楚区分企业事实、行业基准、样本内排名、判断边界和待核实事项；
5. 逐步补齐哈工智能、赛为智能的 2025 年材料，再决定是否纳入正式同行样本。

正式验收标准：报告不将行业事实替代企业事实；只表述样本内比较，不夸大为全行业排名或信用评分；信息不足不改写为负面事实；每个判断均可回溯到已批准画像、行业要点、指标或分方向报告；人工批准前的试验结果不进入正式综合结论。

### 8.6 客户风险评级报告实现大纲

#### 目标

在 11 个分方向报告完成后，为每家企业生成一份可读的客户风险评级报告。同行方向排名不是必需输入，有排名时仅补充相对位置。输出为 21 个等级：`AAA1`、`AAA2`、`AAA3`、`AA1`、`AA2`、`AA3`、`A1`、`A2`、`A3`、`BBB1`、`BBB2`、`BBB3`、`BB1`、`BB2`、`BB3`、`B1`、`B2`、`CCC1`、`CC1`、`C1`、`D1`，不使用“各方向名次分简单相加”的方式替代业务判断。

综合评定是风险辅助审查结果的一部分，不等同于银行内部信用评级、授信额度或自动审批结论。等级只表示当前材料、当前评定标准和（如有）同行样本下的审查结论。

#### 输入边界

综合评定模型不读取原始 PDF、不读取完整企业画像，也不读取其他企业的完整比较卡。Python 为单家企业组装一份固定结构的“综合评定包”，只包含：

1. **评定边界**：企业名称、画像报告期；如启用同行增强，再加入同行样本名称、样本报告期和入样规则；存在跨期假设时必须明确写出原始报告期和试验性质；
2. **11 个方向结论卡**：每个方向的一句话总结、各审批点判断、每个审批点 1～2 条已引用的关键企业事实、信息缺口和分方向报告 ID；
3. **本企业的同行位置（可选）**：该方向的样本内名次、可比较企业数、名次分、所在分组理由；未启用同行比较时为空；不可比较时保留不可比较原因；不传入其他企业的完整信息；
4. **少量跨方向关键指标**：只保留在已批准方向报告中已使用的收入、现金流、研发投入、知识产权、商业化等关键指标及其报告期、口径和样本内名次；
5. **相关行业基准**：只保留已被分方向报告引用的行业机会、技术路线、商业化阶段和行业风险，作为外部参照，不能单独证明企业优劣；
6. **引用索引**：分方向报告 ID、画像项 ID、行业要点 ID、指标 ID 和证据 ID，供输出校验和人工追溯。

报告过长时，先按方向生成固定长度的结论卡，再传入综合评定模型；不得为了压缩输入静默删除某个方向，也不得重新让模型从 PDF 检索事实。

#### 固定评定框架

模型必须按以下五类问题进行整体判断，而非计算平均名次：

1. 行业与商业化基础：市场空间、竞争位置、产品落地和持续经营支撑；
2. 技术与转化能力：技术积累、知识产权、研发组织和成果转化；
3. 治理与资本基础：企业规范性、控制权稳定性、核心团队和股权融资支持；
4. 财务与经营韧性：收入、现金流、融资、经营变化及其信息边界；
5. 合规与重大不确定性：风险事项、反洗钱与制裁、材料缺口和跨期可比性。

方向排名只作为相对位置证据。单项靠前不能自动提高等级；已有明确重大风险不能被多个靠前名次简单抵消；信息不足只能形成判断边界或降低判断把握度，不能自动被解释为负面事实。

等级定义固定为：

| 等级 | 通用含义 |
|---|---|
| A | 核心能力、商业化、治理和经营支撑总体较强，现有材料未显示需优先处置的重大不确定性。 |
| B | 存在明确优势和支撑基础，但仍有需要持续跟踪、核实或缓释的风险与短板。 |
| C | 多个关键方向存在明显短板、经营压力、治理/合规问题或重要信息不足，整体判断应审慎。 |
| D | 已有材料支持存在较显著且可能影响审查结论的经营、财务、治理或合规风险。 |

等级应由模型依据固定框架做整体判断，不允许 Python 根据名次分自动推导；模型也不得自行发明新的等级或输出授信额度、利率、审批建议。

#### 模型输出与校验

DeepSeek 使用 `thinking` 模式，输出固定 JSON：

```text
EnterpriseOverallAssessment
├── assessment_id
├── cohort_id
├── case_id
├── rating_level                 # AAA1 … D1（共 21 级）
├── overall_judgment             # 面向人员阅读的综合判断
├── rating_rationale             # 五类问题下的综合依据
├── core_risks                   # 主要风险
├── mitigating_factors           # 缓释因素或优势
├── rating_boundaries            # 信息、报告期和样本边界
├── verification_priorities      # 优先核实事项
├── source_direction_report_ids
├── source_direction_ranking_keys # cohort_id + section_id
├── evidence_refs
└── review_status                # pending / approved / rejected
```

Python 只做必要校验：等级必须为 21 级信用评级之一，并且必须符合固定边界；11 个方向报告必须完整且已批准；方向排名可以为空，已提供的排名只能来自同一同行样本内已批准的结果；引用只能来自综合评定包；跨期或试验样本边界必须保留；模型不得输出额度、利率或自动审批意见。通过校验后保存为 `pending`，人工批准后才作为正式客户风险评级报告展示和导出。

#### 数据状态与试验规则

正式综合评定只允许使用正式同行样本、已批准方向报告和已批准方向排名。当前 `robotics_2025_assumption_test` 的 12 家企业结果可用于演示流程和评估提示词，但其综合评定必须标记为试验性、保持 `pending`，不得替代正式结果。

方向未启用排名或企业被标记为不可比较时，综合评定仍可使用该方向报告和信息边界；不得因缺少某一个方向名次而停止整体判断，也不得将其视为末位。

### 8.7 单一客户风险评级报告

当前的分方向报告、方向排名和 21 级综合评定均保留为可追溯中间结果。面向业务用户的主输出统一为“客户风险评级报告”：单企业模式每个企业一份，同行增强模式每个企业每个同行样本一份；顶部显示推进建议、客户风险评级、强约束不通过数量、弱约束不通过数量和总体判断，下方按风险评级指引顺序折叠展示 11 个方向。

强约束固定为股权结构安排、反洗钱和制裁合规管理要求；财务情况固定为弱约束。强约束仅在当前材料明确披露硬性触发事实时可判定不通过，任一强约束不通过即得到“不建议推进”。无强约束不通过时，弱约束不通过只使建议变为“有条件推进”，不单独否决。

最终报告的“信息不足”仅表示无法根据当前材料形成实质判断；如材料已明确披露直接影响某方向的不利事实，模型必须判为该方向“不通过”，并可同时保留信息缺口。不得以信息不足覆盖已披露风险事实。

量化评估工具应用仅反映样本与指标口径是否可用，不作为企业风险不通过项，也不计入弱约束不通过数量。试验样本的量化评估固定展示为信息不足和流程验证边界。

21 级评级独立于推进建议：按强约束失败、弱约束失败数量确定等级组，再按非量化“有条件通过/信息不足”方向数确定同组内数字；AAA、AA、A、BBB、BB 使用 1/2/3 三档，B 使用 1/2 两档，CCC、CC、C、D 各一档。量化评估的试验性信息不足不影响等级；至少 2 条强约束失败为 D1，恰有 1 条强约束失败为 C1。

验收重点不是等级分布是否“好看”，而是每个等级能否解释清楚：为何为该等级、哪些方向支撑、哪些风险无法被优势抵消、哪些信息不足限制判断，以及所有结论是否可回溯。
