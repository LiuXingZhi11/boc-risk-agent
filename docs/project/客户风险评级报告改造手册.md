# 客户风险评级报告改造手册

## 1. 需求

最终面向业务人员的汇总结果统一称为“客户风险评级报告”，不再称为“授信审批报告”。报告仍然逐条展示授信指引方向、约束类型、判断状态、依据和核实事项，但综合等级采用 21 级信用评级：

评级采用 21 级，按字母顺序和数字从小到大递减：

`AAA1、AAA2、AAA3、AA1、AA2、AA3、A1、A2、A3、BBB1、BBB2、BBB3、BB1、BB2、BB3、B1、B2、CCC1、CC1、C1、D1`。

其中 AAA 为很好，AA 为较好；每个带三档的等级中，数字越小表示同一等级内的信息越完整、风险边界越小。D1 为最低等级。

“通过、条件通过、不通过”和推进建议仍然保留，评级是风险分层，不直接等同于审批结论，也不输出额度、利率或自动审批决定。

## 2. 评级判定

评级由 Python 根据已经校验的方向状态计算，模型只负责提供方向判断、总体说明和证据引用。量化评估方向的试验性信息不足不计入企业风险条数。

| 等级组 | 固定判定边界 |
| --- | --- |
| AAA1/2/3 | 无强约束或弱约束失败且无非量化信息不足；按非量化“有条件通过”方向数分为 1/2/3 档，数量 0-1、2-4、5 条及以上 |
| AA1/2/3 | 无强约束或弱约束失败，但存在非量化信息不足；按同一信息边界数量分为 1/2/3 档 |
| A1/2/3 | 1 条弱约束失败；按其余非量化不确定方向数分为 1/2/3 档 |
| BBB1/2/3 | 2 条弱约束失败；按其余非量化不确定方向数分为 1/2/3 档 |
| BB1/2/3 | 3 条弱约束失败，且未达到 CC 组合门槛；按其余非量化不确定方向数分为 1/2/3 档 |
| B1/2 | 4 条弱约束失败，且未达到 CC 组合门槛；不确定方向数不超过 2 条为 B1，否则为 B2 |
| CCC1 | 5 条及以上弱约束失败，但未达到 CC 组合门槛 |
| CC1 | 至少 3 条弱约束失败，且同时覆盖企业规范性和财务情况 |
| C1 | 恰有 1 条强约束失败 |
| D1 | 至少 2 条强约束失败 |

当多个条件同时满足时，采用更低等级：强约束失败优先于 CC，CC 优先于 CCC。等级顺序由高到低固定为上表顺序，不允许模型自行改写边界。

## 3. 实现步骤

1. 将领域模型、综合评定校验和 SQLite 新建表约束统一为 21 级等级集合。
2. 将综合评定校验改为按方向状态计算期望等级，并要求模型返回值与 Python 计算结果一致。
3. 更新综合评级提示词，明确报告名称、21 级边界、输出字段和“评级不等于自动审批”的限制。
4. 更新最终报告 Markdown、Streamlit 导航、按钮、下载文件和状态提示中的名称；内部函数名和数据库表名暂不改动，避免无必要的数据迁移。
5. 对已有数据库执行轻量迁移：保留原方向状态、判断和证据，只按已保存状态重新映射 21 级评级，不调用模型，并重建评级检查约束。
6. 更新单元测试，覆盖 21 级边界、旧记录迁移、报告名称和页面入口。

## 4. 不在本次范围内的内容

- 不改变 11 个授信指引方向、强弱约束定义和同行排名算法。
- 不把方向名次相加或平均成评级。
- 不新增权限、额度、利率或自动审批逻辑。
- 仅保留内部兼容性的旧函数名、数据库表名和历史文件名；用户可见名称统一为“客户风险评级报告”。

## 5. 后续行动建议展示

后续行动建议仍由模型输出 3 至 8 条独立行动，但每条只解决一个问题，不把多个方向合并成一段话。报告展示时按编号分点，并使用每条建议的“行动”字段作为该条标题；正文不再重复“行动”字段，只将行动类型、优先级、原因、关联方向、所需材料、建议时点和完成标准分行显示。已有数据库中的长字符串也必须按分号字段拆分展示，不要求重新调用模型。

实现步骤：

1. 在行动建议提示词中限制每条建议只对应一个方向或一个核实事项，并要求使用固定字段标签；
2. 保持数据库字段为字符串数组，避免为展示格式增加迁移；
3. 在 Markdown 导出和页面展示层将每条建议渲染为编号条目及字段子项；
4. 对没有固定字段标签的历史文本，仍保留原文并作为单条建议显示。
