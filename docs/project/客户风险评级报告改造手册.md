# 客户风险评级报告改造手册

## 1. 需求

最终面向业务人员的汇总结果统一称为“客户风险评级报告”，不再称为“授信审批报告”。报告仍然逐条展示授信指引方向、约束类型、判断状态、依据和核实事项，但综合等级采用九级信用评级：

`AAA、AA、A、BBB、BB、B、CCC、CC、C`。

“通过、条件通过、不通过”和推进建议仍然保留，评级是风险分层，不直接等同于审批结论，也不输出额度、利率或自动审批决定。

## 2. 评级判定

评级由 Python 根据已经校验的方向状态计算，模型只负责提供方向判断、总体说明和证据引用。量化评估方向的试验性信息不足不计入企业风险条数。

| 等级 | 固定判定边界 |
| --- | --- |
| AAA | 无强约束失败、无弱约束失败，且无非量化关键信息不足 |
| AA | 无强约束失败、无弱约束失败，但存在非量化关键信息不足 |
| A | 1 条弱约束失败 |
| BBB | 2 条弱约束失败 |
| BB | 3 条弱约束失败，但未同时达到规范性与财务风险组合门槛 |
| B | 4 条弱约束失败，但未同时达到规范性与财务风险组合门槛 |
| CCC | 5 条及以上弱约束失败，但未达到 CC 的组合门槛 |
| CC | 至少 3 条弱约束失败，且同时覆盖企业规范性和财务情况 |
| C | 任一强约束失败 |

当多个条件同时满足时，采用更低等级：强约束失败优先于 CC，CC 优先于 CCC。等级顺序由高到低固定为上表顺序，不允许模型自行改写边界。

## 3. 实现步骤

1. 将领域模型、综合评定校验和 SQLite 新建表约束统一为九级等级集合。
2. 将综合评定校验改为按方向状态计算期望等级，并要求模型返回值与 Python 计算结果一致。
3. 更新综合评级提示词，明确报告名称、九级边界、输出字段和“评级不等于自动审批”的限制。
4. 更新最终报告 Markdown、Streamlit 导航、按钮、下载文件和状态提示中的名称；内部函数名和数据库表名暂不改动，避免无必要的数据迁移。
5. 对已有数据库执行轻量迁移：将旧 A/B/C/D 记录按旧边界映射为 AAA/AA/CCC/C，并重建评级检查约束；不存在旧表时直接使用新约束。
6. 更新单元测试，覆盖九级边界、旧记录迁移、报告名称和页面入口。

## 4. 不在本次范围内的内容

- 不改变 11 个授信指引方向、强弱约束定义和同行排名算法。
- 不把方向名次相加或平均成评级。
- 不新增权限、额度、利率或自动审批逻辑。
- 仅保留内部兼容性的旧函数名、数据库表名和历史文件名；用户可见名称统一为“客户风险评级报告”。
