# 企业画像主题分析故障处理手册

## 需求

主题分析调用失败时，页面必须保留失败原因，不能立即刷新导致用户误以为“没有变化”。已保存的结构化事实和画像内容不得因分析失败被修改。

## 实现步骤

1. 主题分析只有在模型返回合法且通过引用校验的结果后才写入主题分析表。
2. 成功时刷新页面，使已保存的主题结论显示在对应领域下。
3. 失败时保留当前页面状态，展示失败原因、已读取主题和重试提示，不执行自动刷新。
4. 重新点击按钮只重试主题分析，不重新抽取事实、不重复导入 PDF。

## 3. ReAct 与 JSON 合成分工

ReAct 只负责按主题读取已审核事实；其最后一条自然语言回复不作为正式分析结果。读取完成后，系统把本轮已读取的主题事实交给独立的 JSON 合成调用，并只接受该调用通过 JSON 解析和引用校验后的结果。

这样可以保留 ReAct 的按需读取能力，同时避免 Agent 最后一条回复使用自然语言或其他格式而导致主题分析无法保存。

## 4. 结果字段归一化

模型可能返回主题分析数组，但遗漏 `domain_summary`，也可能把主题数组写成单个对象、按主题 ID 映射的字典或 JSON 字符串。在正式校验前，系统可以把这些等价结构归一化为数组，并使用同一结果中已有的非空主题结论拼接领域摘要；如果主题结论本身缺失，仍然拒绝保存并展示错误。归一化只重组模型已经返回的内容，不补充外部事实。

## 5. 空领域摘要的处理要求

实际模型有时会返回 `domain_summary` 字段但值为空，或使用 `overall_conclusion`、`domain_conclusion`、`topic_summary` 等等价字段。处理顺序如下：

1. 优先读取正式字段和常见等价字段，将非空文字统一到 `domain_summary`；
2. 如果领域摘要仍为空，使用已经返回且通过引用校验的主题结论或主题关键信号合成摘要；
3. 如果模型确实没有返回任何可归纳文字，使用“当前已读取事实暂未形成可归纳的本领域结论，请补充或核实相关信息”的中性边界提示，不能编造企业事实；
4. 主题覆盖、事实引用和证据引用仍必须通过原有校验，不能因为补齐摘要而放宽引用约束。

提示词同时要求 `domain_summary` 必须为非空字符串；模型没有足够事实时，应明确写信息不足，而不是返回空字符串。

## 6. 主题数组的处理要求

`topic_analyses` 是固定的数组接口，不因领域变化而改变。模型必须为运行时主题目录中的每个主题返回一个对象；主题较少时也必须返回数组，不能返回单个对象、空对象或只返回一段自然语言。代码允许将按主题编号组织的对象、JSON 字符串和常见中文别名归一化为数组；如果没有任何主题分析内容，仍然拒绝保存并提示模型输出不完整，不能用空数组冒充完成。

## 验收标准

- 模型输出格式错误时，页面能看到具体错误，而不是静默回到原画像；
- 主题分析失败不改变原有事实数量、证据引用和画像状态；
- 主题分析成功后，结论显示在对应主题的展开区域中。
