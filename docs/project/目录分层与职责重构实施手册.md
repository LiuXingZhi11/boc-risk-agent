# 项目目录分层与职责重构实施手册

## 1. 目标

在不破坏当前运行流程的前提下，明确业务规则、运行代码、数据材料和可选扩展平台的边界，降低目录重复造成的理解成本。

## 2. 当前边界

### 2.1 可维护内容

```text
prompts/       业务提示词、字段语义和分析规则
authorization/ 权限规则和字段可见性配置
config/         模型、MCP 和 Skill 开关配置
skills/         具体 Skill 的 skill.yaml 与 SKILL.md
materials/      企业、行业和参考材料
data/           当前运行数据库及上传材料
```

这些目录中的内容可以由业务人员或平台管理员按对应手册维护。

### 2.2 Python 运行代码

```text
src/profiles/       企业画像流程
src/industry/       行业背景流程
src/approval/       风险评级、排名和综合报告
src/sources/        PDF/HTML 导入和切片
src/evidence/       证据存储和查询
src/llm/            DeepSeek 调用
src/ontology/       本体加载和校验
src/authorization/  权限判断代码
src/prompts/        提示词文件加载器
src/platform/mcp/   MCP 连接、工具调用和审计代码
src/platform/skills/ Skill 加载、校验和运行适配代码
src/storage/        SQLite 初始化和数据库结构
src/ui/             Streamlit 页面服务
```

`src/` 中的文件是程序实现，不应由业务人员直接修改来维护业务规则。

## 3. Skill 与 MCP 的对应关系

```text
skills/<skill>/skill.yaml + SKILL.md
        ↓
src/platform/skills/ 读取、校验和运行 Skill
        ↓
src/platform/mcp/    发现并调用外部 MCP 工具
        ↓
config/mcp_servers.yaml 连接配置
```

根目录 `skills/` 是 Skill 定义，不是 Python 包；`src/platform/skills/` 是运行这些定义的 Python 代码。两者不能合并。

## 4. 分阶段实施步骤

### 第一阶段：职责标注

1. 为 `skills/`、`src/platform/skills/` 和 `src/platform/mcp/` 增加目录说明；
2. 更新 README 和目录说明，明确配置文件与运行代码的对应关系；
3. 不移动文件、不修改 import、不改变数据库结构；
4. 运行完整自动化测试。

### 第二阶段：页面服务拆分

将过大的 `src/ui/v5_services.py` 按材料管理、企业画像、行业背景和风险评级拆分。拆分只改变文件组织，不改变公开服务函数行为。

### 第三阶段：可选平台归组

MCP 和 Skill 的 Python 运行代码统一位于 `src/platform/`：

1. `src/platform/mcp/` 负责 MCP Provider、工具调用和审计；
2. `src/platform/skills/` 负责 Skill 加载、校验和运行时适配；
3. 根目录 `skills/` 定义文件和 `config/` 配置文件保持不移动；
4. 关闭 MCP/Skill 开关时，核心业务流程保持不变；
5. 源码、测试和手册中的 import 与路径已经同步；
6. 完整测试和模块导入检查已经通过。

## 5. 验收标准

- 业务人员能区分“可修改的定义文件”和“不可直接修改的 Python 代码”；
- Skill 定义可以在不修改 `src/platform/skills/` 的情况下被加载和校验；
- MCP/Skill 开关关闭时，企业画像、行业背景和风险评级流程不受影响；
- 完整测试通过，且没有新增旧目录或重复实现。
