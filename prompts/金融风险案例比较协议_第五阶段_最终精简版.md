# 金融风险案例比较协议（第五阶段｜最终精简版）

> 旧版风险案例比较模块专用，不参与当前企业画像、11 个审批方向、综合 A-D 评级或推进建议主流程。

## 0. 输出格式硬约束（优先执行）

1. 只能输出一个合法 JSON 对象，不得输出 Markdown、代码围栏、解释文字或自我检查。
2. 顶层字段只能是：`historical_case_id`、`similarities`、`differences`、`applicable_rule_hypotheses`、`uncertainties`；如果系统附带 `api_meta`，由系统处理，不由模型主动生成。
3. `historical_case_id` 必须是输入历史案例中的原样 `case_id` 字符串。
4. `similarities`、`differences`、`applicable_rule_hypotheses`、`uncertainties` 必须是数组；没有内容时必须输出空数组 `[]`。
5. `uncertainties` 必须是纯文本字符串数组：

   ```json
   "uncertainties": ["尚未明确的信息一", "需要进一步核实的信息二"]
   ```

   不得输出对象、嵌套数组、数字、布尔值或 `null`；没有不确定事项时输出 `"uncertainties": []`。
6. `similarities` 中每一项必须包含字符串 `description`、字符串数组 `new_case_fact_ids`、字符串数组 `historical_fact_ids` 和 `confidence`；`confidence` 只能是 `high`、`medium`、`low`。
7. `differences` 中每一项必须包含字符串 `description`、字符串数组 `new_case_fact_ids`、字符串数组 `historical_fact_ids` 和 `importance`；`importance` 只能是 `high`、`medium`、`low`。
8. `applicable_rule_hypotheses` 中每一项必须包含 `rule_id`、`applicability`、`reason`；`rule_id` 必须来自输入历史案例，`applicability` 只能是 `relevant`、`partially_relevant`、`not_supported`，`reason` 必须是非空字符串。
9. 所有事实 ID 必须来自对应输入案例，不得新增、改写或臆造 ID。

## 1. 任务目标

比较一个新案例和一个历史案例，只输出证据支持的相似点、差异、历史规则参考和不确定性。

## 2. 证据约束

- 新案例事实只能填入 `new_case_fact_ids`，历史事实只能填入 `historical_fact_ids`；
- 不得因为历史案例有某事实，就断言新案例也有该事实；
- 缺失信息必须写入 `differences` 或 `uncertainties`；
- 相似理由和差异必须基于输入事实；
- 历史规则只能作为参考机制，不得生成审批、授信、风险定级或业务决策结论；
- 只能引用输入中的规则 ID。

## 3. 输出示例

```json
{
  "historical_case_id": "CASE_HIST_001",
  "similarities": [
    {
      "description": "两案均存在关联方资金往来",
      "new_case_fact_ids": ["NEW_CASE_F001"],
      "historical_fact_ids": ["CASE_HIST_001_F002"],
      "confidence": "medium"
    }
  ],
  "differences": [],
  "applicable_rule_hypotheses": [],
  "uncertainties": ["新案例尚未明确资金往来的真实交易背景"]
}
```
