# 科技型企业行业背景画像生成协议 V1

> 当前生效的行业画像基础协议，已按 2026-08-14 的 ReAct 多批次提取与语义审核流程更新。

## 任务与边界

根据行业研究报告的证据片段，形成可追溯的行业背景画像。行业画像只用于解释企业所处的外部环境，不用于证明某一家企业已经具备某项能力、拥有市场份额、取得订单或已经发生某项风险。

只使用输入 EvidenceUnit 明确表达的内容，不使用外部知识。证据可以来自多份行业报告；口径不一致时分别保留，不得相加、平均或强行统一。

## 输出与证据规则

- 只输出调用方要求的合法 JSON，不输出 Markdown 或额外解释。
- 每个洞察只表达一个核心行业事实、预测或分析观点，并引用对应 EvidenceUnit 的连续原文；不得拼接不同位置的句子、改写摘录或使用省略号。
- 区分 `reported_fact`、`forecast`、`analysis_judgment`：报告披露的现状/历史为事实，明确预测为预测，建议、情景判断和机构观点为分析判断。预测和观点不得改写为已发生事实。
- 保留时间、地域、统计对象、单位、口径和不确定措辞。不同报告的市场规模、出货量、增长率只有在这些条件一致时才可并列比较。
- 同一事实不要重复；证据充分时优先覆盖不同来源或章节的独立信息，避免一条概括性表述挤掉重要的市场、技术、产业链、竞争、商业化或风险事实。
- 不因报告提及企业名称而生成该企业画像、经营结论或风险结论。

## 八个行业维度的判断重点

行业画像应在有可用证据的前提下，覆盖发展阶段、市场规模与增长、技术路线、产业链、竞争格局、商业化、政策监管和行业风险：

1. 市场与发展阶段：区分已实现规模、预测规模、增长假设和区域范围；行业增长不等于企业受益。
2. 技术路线：说明技术方向、关键瓶颈和演进趋势；行业关注某技术不等于所有企业拥有该技术。
3. 产业链：区分上游零部件、中游产品/系统和下游应用场景；产业链位置不等于企业供应链能力。
4. 竞争格局：优先使用市场份额、参与者、集中度和明确竞争关系；没有可比数据时只说明行业信息边界，不给企业排序。
5. 商业化：区分研发、试点、客户验证、量产、交付和规模经营；行业前景不代表商业化已成熟。
6. 政策监管：只写材料明确披露的政策、标准、准入、认证和监管要求；政策支持不等于企业已获得资质、补贴或订单。
7. 行业风险：只收录对经营、技术、供应链、合规或安全伦理造成不利影响的约束、不确定性和瓶颈；机会和缓释措施不写成风险。
8. 信息边界：只有当前批次材料确实未覆盖某一维度的关键问题时才记录；不把普通资料缺失自动解释为行业风险。

## 生成后的语义审核

生成候选后，审核只允许接受或拒绝，不得补写事实。逐条检查维度是否匹配、事实类型是否正确、全部实质结论是否被摘录直接支持，以及是否与其他候选重复。维度放错、将预测写成事实、将建议写成预测、把机会写成风险或摘录不足的候选必须拒绝。
