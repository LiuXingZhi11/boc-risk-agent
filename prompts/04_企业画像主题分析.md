# 企业画像主题分析

> 审阅镜像。输入不是 PDF，而是已审核的结构化事实及其证据摘要。

```text
你负责分析企业画像中的一个领域，不负责抽取新的原始事实。
企业：{{enterprise_name}}
领域：{{dimension_label}}

必须使用 read_topic 读取每个有事实的主题；事实超过单次上限时继续读取下一页。
只能根据读取到的事实、统计结果和证据摘要进行分析。
分析应说明企业特征、变化趋势、经营含义和信息边界，不能只复述字段和值。
每个主题的 fact_refs 只能引用该主题 read_topic 返回的事实。
证据不足时写明“未披露”或“无法判断”，不得补造事实。
最终只输出 JSON，不要输出 Markdown。

输出：domain_summary、topic_analyses、information_boundaries、evidence_refs。
每个 topic_analyses 项包含 topic_id、conclusion、key_signals、information_boundaries、fact_refs、evidence_refs。
不得新增原文没有的数字、名称、关系或确定性风险结论。
```

## 当前画像展示的 6 个大维度及主题

| 大维度 | 内部主题 |
|---|---|
| 企业与团队 | 企业定位与发展阶段；控制权与治理机制；核心团队与人员结构 |
| 技术与知识产权 | 核心技术体系与来源；技术成熟度与转化；知识产权与权利状态 |
| 产品与商业化 | 产品与服务布局；商业化阶段与交付 |
| 客户、供应商与合作方 | 客户结构与集中度；主要客户交易与依赖；供应商结构与采购依赖；主要供应商交易与依赖 |
| 财务与融资 | 收入与盈利表现；现金流与偿债基础；研发投入；财务口径客户集中度 |
| 风险与合规 | 已披露风险事项；材料缺口与判断边界 |

模型会先拿到上述主题目录，然后必须逐主题调用 `read_topic` 读取已审核事实。主题的字段归并规则在 `src/profiles/visual_card.py` 的 `TOPIC_DEFINITIONS` 中。

## 分析逻辑（当前实现）

对每个非空主题依次执行：

1. 读取该主题所有已审核事实；事实过多时分页读完；
2. 先归纳“企业有什么、发生了什么变化”，不得混入其他主题事实；
3. 再说明这些事实在经营上意味着什么，例如技术是否已有产品化证据、收入和现金流是增长还是承压、客户集中度是否存在；
4. 最后单列无法判断的内容，例如未披露有息负债、无市场份额指标；
5. 每个结论必须引用已读取事实和证据。信息不足只能限制判断，不能反写为负面事实。

注意：这里的“经营含义”是相对克制的画像分析，不产生 A-D 结论，也不产生授信建议。

## 企业画像主题分析业务规则

### 通用规则

1. 每个主题先形成一句能够概括企业特点的结论，再列出支撑该结论的具体事实；不得将同类原子事实逐条拼接为结论。
2. 结论应同时回答“企业具有什么特征”“该特征由哪些事实支撑”“仍有哪些不能判断的边界”。三者缺一不可。
3. 对时间序列事实，优先呈现连续报告期的变化方向、幅度和拐点；不得只选对企业有利或不利的单一年份。
4. 对数量事实，必须保留统计范围、期间和口径。专利申请、授权、存量、新增量、境内外子集不能互相替代。
5. 对“自主研发、已商业化、已量产、无重大事项”等状态，只能按原文明确表达的范围表述；不得从产品名称、成立年限或单一宣传语推导状态。
6. 事实重复时应合并为企业特征，例如将多笔客户交易归纳为客户集中度、客户类型或依赖结构；不得将每笔金额当成独立画像结论。
7. 信息未披露、证据不足或口径不一致时，只能写“无法判断、待核实或存在信息边界”；不得推定为零、风险或优势。
8. 主题分析不得把行业普遍趋势直接写成企业已经具备的能力、市场份额、订单或竞争位置。

### 各主题判断重点

| 主题 | 应重点回答的问题 | 不得作出的推断 |
|---|---|---|
| 企业定位与发展阶段 | 主营业务是什么、业务覆盖哪些场景、材料是否明确披露发展阶段 | 不得根据成立时间或营收规模自行判定初创、成熟或转型 |
| 控制权与治理机制 | 实控人、控制安排、激励和已披露治理事项是否清楚 | 未入库的持股、质押或协议明细只能作为待核实事项 |
| 核心团队与人员结构 | 创始人及关键人员的可核验经历、能力覆盖与稳定性线索 | 不得按学历高低或简历长短给团队优劣评分 |
| 核心技术体系与来源 | 技术名称、来源、自研/合作/依赖情况和技术体系覆盖 | 技术名词数量不等于技术先进性 |
| 技术成熟度与转化 | 每项具体技术是否有样机、验证、量产、产品化或收入支撑 | 不得将表格表头、研发计划或单一产品宣传等同于全部技术已量产 |
| 知识产权与权利状态 | 专利和其他知识产权的数量、范围、权属和限制情况 | 专利数量不等于技术质量、市场壁垒或无侵权风险 |
| 产品与服务布局 | 已披露产品矩阵、产品类别和应用方向 | 研发项目、零部件或客户名称不得误写为产品 |
| 商业化阶段与交付 | 产品处于研发、试点、商业化或规模交付的直接证据 | 有产品或有收入不自动等于所有产品实现规模商业化 |
| 客户/供应商结构 | 集中度、关联关系、地域和交易对手披露范围 | 年报中的“第一名/客户A”等代称不等于异常客户或合规风险 |
| 客户/供应商依赖 | 交易金额、占比、波动、单一依赖及供应连续性线索 | 单笔交易金额不能单独代表客户价值或供应链风险 |
| 收入与盈利表现 | 收入、利润、扣非利润的连续变化及各自口径 | 归母、扣非归母和普通净利润不得混用 |
| 现金流与偿债基础 | 经营现金流、期末现金、有息负债和持续经营相关事实 | 未披露债务余额不等于无债务或高债务 |
| 研发投入 | 研发费用、研发费用率及其变化 | 研发费用率高低不能单独证明技术领先或经营质量 |
| 已披露风险事项 | 已发生或明确提示的技术、经营、财务、法律和合规事项 | “未发生重大诉讼/处罚”等否定表述不得转成风险事实 |
| 材料缺口与判断边界 | 当前材料不能验证的关键事项及其影响范围 | 信息缺口不得包装成企业负面结论 |
