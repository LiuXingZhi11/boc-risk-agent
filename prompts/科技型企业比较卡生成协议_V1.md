# 科技型企业比较卡生成协议 V1

> 兼容协议：用于历史画像候选召回，不参与当前同行分方向排名、综合 A-D 评级或推进建议。

## 定位

`EnterpriseComparisonCard` 是从已审核 `EnterpriseProfile` 派生的检索对象，用于相似历史企业的候选召回。

它不是新的事实来源，不替代企业画像，不输出风险评分，也不能反向修改画像。

## 输入

输入只包含已审核画像项、画像关系、信息缺口和冲突，不包含 PDF/HTML 原始长文。

## 输出格式

只输出一个合法 JSON 对象：

```json
{
  "comparison_dimensions": [
    {
      "dimension_id": "technology_and_ip",
      "summary": "企业的核心产品依赖外部许可的蓝光存储技术，并承担专利池授权费用。",
      "comparison_terms": ["蓝光存储", "外部技术许可", "专利池", "授权费用"],
      "source_item_ids": ["item-1", "item-2"],
      "source_relation_ids": ["relation-1"],
      "information_gaps": []
    }
  ]
}
```

每个维度只能包含：

```text
dimension_id
summary
comparison_terms
source_item_ids
source_relation_ids
information_gaps
```

不得输出：

```text
score
risk_level
structured_features
relation_signatures
evidence_unit_ids
```

后三类结构化和证据字段由程序从所引用的画像项计算，避免模型改写来源。

## 固定比较维度

```text
enterprise_and_team
technology_and_ip
product_and_commercialization
customer_supplier_and_dependency
finance_and_funding
risk_and_compliance
authority_outcome_and_evidence
```

没有有效事实的维度可以省略，不要用“暂无信息”“信息不足”等通用文本填充检索内容。

## 摘要要求

- 每个摘要只描述该维度中已有、有区分度的事实。
- 建议 40 至 160 个汉字。
- 不补充常识，不推断因果，不输出综合风险等级。
- 不从画像数值另行计算衍生指标；没有画像明确记录的比较基准时，不使用“高”“低”“异常”“不足”“领先”或“不匹配”等相对评价。
- 保留否定、条件、期间、适用范围和信息角色，不得把未发生、不适用、待核实或企业自述改写为肯定事实。
- 不合并不同类型的主体和角色；自然人、法人组织、技术、产品以及股东、控制人、关联方等应保持画像中的原有类型和关系。
- 不重复固定模板标题。
- 历史结果、监管认定与企业自述必须保持原有语义角色。

## 比较词要求

- 每个维度提取 2 至 12 个变量词。
- 优先实体、技术、产品、依赖关系、经营特征和具体风险概念。
- 不使用“企业、情况、风险、信息、经营”等无区分度词。
- 不要求把所有表达映射到人工维护的封闭词表。
- 比较词应忠实反映画像事实，不得为了提高召回率删除关键限定或制造画像中不存在的同义关系。

## 来源约束

- `source_item_ids` 和 `source_relation_ids` 必须逐字复制输入画像中的 ID。
- 每个维度至少引用一个来源项。
- 摘要和比较词必须能由引用来源支持。
- 程序根据来源项自动继承 `evidence_unit_ids`。

## 更新规则

比较卡记录：

```text
profile_id
ontology_version
profile_hash
```

画像内容或 Ontology 版本变化后，旧比较卡失效并重新生成。
