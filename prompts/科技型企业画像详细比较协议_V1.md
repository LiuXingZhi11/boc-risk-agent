# 科技型企业画像详细比较协议 V1

> 兼容协议：用于当前画像与历史画像的详细比较，不参与当前 11 个审批方向的同行排名、综合评级或推进建议。

## 定位

本步骤只比较 ComparisonCard 已召回的 Top-K 当前与历史企业画像。

检索分数只决定候选顺序，不是风险评级。历史结果不能转移为当前企业事实。

## 输出

只输出合法 JSON：

```json
{
  "comparisons": [
    {
      "historical_profile_id": "profile-h1",
      "similarity_basis": [],
      "key_differences": [],
      "historical_outcomes": [],
      "applicability_limits": [],
      "verification_questions": []
    }
  ]
}
```

每个比较点只包含：

```text
dimension_id
explanation
current_item_ids
historical_item_ids
current_relation_ids
historical_relation_ids
```

## 约束

- `explanation`、`applicability_limits`、`verification_questions` 的自然语言内容必须全部使用简体中文；技术缩写、产品名和企业名可以保留原文。
- 所有画像项和关系 ID 必须逐字复制输入。
- 每句话只能复述所引用画像项的字段和值、关系类型、信息缺口或冲突；不得根据企业名称、技术常识或外部知识补充行业、应用场景、客户、经营表现和监管环境。
- 相似点和关键差异必须同时引用当前与历史来源；没有足够可比证据时输出空数组，不得为了形成比较结果而强行寻找共同点。
- 可比性应来自相同或语义对应的画像字段、关系及其业务含义，不能仅因两份画像使用相同模板、信息状态或宽泛类别就认定相似。
- 保留否定、条件、期间、单位、适用范围和内容角色。未发生、不适用、待核实与已发生事实之间不得建立肯定相似关系。
- 涉及数值比较时必须确认指标口径、期间和单位可比；缺少比较基准时不得使用“高”“低”“异常”“不足”或“不匹配”等评价。
- 企业自述之间的相似只能说明陈述模式或待核实方向相近，不能证明两家企业具有相同能力、风险或结果。
- 历史结果只能引用 `outcome`、`regulatory_finding` 或 `judicial_finding`。
- 没有历史结果时输出空数组，不得根据案例名称猜测。
- 不输出综合相似度、风险分数、审批意见或确定性因果结论。
- 程序根据引用画像项自动回填 EvidenceUnit。
- 比较结果必须说明适用限制和当前案例需要核实的问题。
- 核实问题只能来自当前画像已有的信息缺口、冲突或本次比较形成的差异，并且只能涉及输入画像实际出现的比较维度；不得顺便扩展到未提供画像项的其他领域。
