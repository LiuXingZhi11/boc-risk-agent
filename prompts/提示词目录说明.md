# 运行时提示词目录

当前按“数据、逻辑、行动、权限”四层组织：数据层提供可追溯事实与行业材料，逻辑层生成分析和评级判断，行动层把最终评级转成业务人员可执行的后续建议，权限层维护可见范围和操作边界。代码运行时读取数据层、逻辑层和行动层的模型提示词；权限不由模型决定。

审批指引的图片转写参考位于 `docs/business/授信审批图片文字提取.md`，不属于运行时提示词；审批方向的可执行结构和模型规则分别由 `src/approval/guideline_definitions.py` 与下表中的逻辑提示词维护。

```text
prompts/data/       # 事实抽取、行业背景和证据调查
prompts/logic/      # 画像分析、审批方向、排名和综合评级
prompts/action/     # 审批后的人工跟进规则
authorization/      # 权限设计（非模型提示词）
```

| 文件 | 运行时接口 | 章节 |
|---|---|---|
| `data/企业画像数据规则.md` | 企业画像数据层 | 固定流程证据选择、ReAct证据调查、结构化事实抽取、关系核验、输出修复 |
| `data/行业背景数据规则.md` | 行业背景数据层 | ReAct证据调查、行业背景生成、行业语义审核、业务口径 |
| `logic/企业画像逻辑规则.md` | 企业画像逻辑层 | 主题分析、输出格式 |
| `logic/授信审批逻辑规则.md` | 客户风险评级逻辑层 | 审批方向报告、同行分方向排名、方向评分与 100 分综合总分、格式修复 |
| `action/行动建议规则.md` | 行动建议模型接口 | 根据客户风险评级报告生成资料补充、事实核验、条件跟踪和人工复核建议 |

## 维护边界

- `prompts/data/企业画像本体.yaml` 定义对象、关系、字段、类型和枚举，是程序接口文件；业务人员不应修改。
- `prompts/data/企业画像字段语义.yaml` 维护字段中文名称、业务解释、同义词和抽取边界，由程序与本体接口合并后提供给模型。
- `prompts/data/企业画像抽取规则.yaml` 定义通用抽取原则和领域补充规则，由 Python 按当前领域整理后提供给模型。
- `prompts/data/企业画像校验规则.yaml` 记录跨字段和跨事实校验约束，供程序校验规则维护和审查，不作为原始字段定义。
- `prompts/logic/企业画像维度映射.yaml` 只定义结构化事实到企业画像调查领域和展示维度的映射，不参与事实字段定义。
- Python 只注入企业、证据、字段白名单、审批点、指标、排名和调用限制，并负责 JSON、证据引用和状态校验。
- 行动建议由 `prompts/action/行动建议规则.md` 约束并调用 DeepSeek 生成；评级、方向状态和推进建议仍由 Python 固定校验，权限规则在 `authorization/`，不由模型决定。
- 当前不再保留旧版兼容提示词。主流程只读取 `data/` 和 `logic/` 中的模型规则；`action/` 保存人工跟进规则。

## 修改验证

修改主目录文件后，应检查相应 `build_*_messages` 的 system prompt，并运行对应测试。不要在 Python 中重新复制一份自然语言业务规则。
