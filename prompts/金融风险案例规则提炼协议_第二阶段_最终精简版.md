# 金融风险案例规则提炼协议（第二阶段｜最终精简版）

> 旧版 `app.py` 兼容入口专用，不参与当前企业画像、11 个审批方向、综合 A-D 评级或推进建议主流程。

## 1. 任务目标

仅根据第一阶段输出的结构化事实，提炼单案例规则假设。

每条输出只回答：

- 当前案例支持怎样的风险过程假设；
- 哪些事实直接支持该假设；
- 该假设仍有哪些不确定性。

本阶段不生成事前风险信号、跨案例规则或正式可执行规则。

## 2. 必须完成

### 2.1 提炼单案例规则假设

`rule_hypothesis` 应用一至两句话概括当前案例直接支持的风险过程。

要求：

- 只使用当前案例中的事实；
- 每个实质性表述都能由 `supporting_fact_ids` 追溯；
- 可以省略不影响风险过程的专名、具体数值和背景信息；
- 使用概括性角色时，不得改变原事实中的关系强度；
- 证据不足时，允许不为该案例生成规则假设。

### 2.2 引用最小充分证据集

`supporting_fact_ids` 只保留足以支持规则假设的最小事实集合。

不得引用：

- 当前案例之外的事实；
- 与规则假设无直接关系的背景事实；
- 仅用于增加表面证据数量的事实。

### 2.3 保留证据边界

- `attributed_assessment` 只能作为有明确来源的判断使用，不得改写为已确认原因；
- `estimate_or_plan` 只能支持计划、预测或估计，不得支持实际结果；
- `uncertain_statement` 不得被改写为确定结论；
- 事后发现的事实可以支持回顾性假设，但不得被描述为事前已知；
- 无法确认的因果、关系或结果必须写入 `uncertainty`。

## 3. 禁止事项

本阶段不得：

1. 重新抽取、改写或补充第一阶段事实；
2. 补充外部知识、常识、行业规律或案例外解释；
3. 增加输入中没有的主体关系、交易路径、行为目的、原因或结果；
4. 将相关、共现或时间先后改写为确定或唯一因果；
5. 提高关系、行为、结果、责任或确定性的语义强度；
6. 使用没有明确比较基准的相对判断；
7. 生成阈值、评分、风险等级、审查方法或处置建议；
8. 生成事前风险信号、跨案例规则或知识图谱内容；
9. 将单案例假设表述为已验证的通用规律；
10. 为填充输出而强行生成规则；
11. 输出重复的名称、摘要、解释层、自我检查或质量评分。

## 4. 输出结构

只输出合法 JSON，不得输出 Markdown 代码块或额外说明。

```json
{
  "single_case_rule_hypotheses": [
    {
      "rule_id": "",
      "case_id": "",
      "rule_hypothesis": "",
      "supporting_fact_ids": [],
      "uncertainty": "",
      "generalization_status": "single_case_hypothesis"
    }
  ],
  "uncertainties": []
}
```

## 5. 输出要求

1. 每条规则只对应一个案例；
2. `case_id` 必须存在于输入；
3. 所有 `supporting_fact_ids` 必须属于对应案例且不得重复；
4. 同一事实链不得拆分为多条重复规则；
5. 只有存在相互独立的风险过程时，同一案例才可生成多条规则；
6. `generalization_status` 固定为 `single_case_hypothesis`；
7. 不得输出任何其他顶层字段。
