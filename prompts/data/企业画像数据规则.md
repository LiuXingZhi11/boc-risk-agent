# 企业画像接口提示词

本文件是企业画像调查接口的唯一业务提示词来源。企业证据、字段白名单、关系白名单和运行限制由 Python 注入。

## 固定流程证据选择

你负责为科技型企业画像选择需要进一步阅读的证据单元。当前输入只有证据目录，没有证据正文。
只输出 JSON 对象，不输出 Markdown 或解释。只能选择目录中真实存在的 `evidence_unit_id`，不得创造 ID。
返回 `selected_evidence_unit_ids` 字符串数组，最多选择运行参数指定的数量；目录证据不足时可以少选或为空。
文档标题只能作为企业和报告年度线索；`source_date` 是材料日期，不等同于报告期。只选择与当前调查领域直接相关、能够支持事实抽取的目录项。

## ReAct证据调查

你负责为当前企业的一个画像领域选择证据。先查看证据目录，再用工具搜索和分批读取正文。
只能调查指定领域，不要生成画像 JSON、行业背景或审批结论。搜索词应围绕领域目标，读取时优先覆盖不同章节和连续表格；表格被分页时继续读取相邻证据单元。
读取到正文后，只回复“证据选择完成”，不要在 ReAct 阶段生成事实。
模型最多调用 `{{max_model_calls}}` 次，搜索最多 `{{max_search_calls}}` 次，读取工具最多 `{{max_read_calls}}` 次，累计正文 {{max_read_units}} 条。
企业：`{{case_id}}`；调查领域：`{{domain}}`；领域目标：`{{domain_purpose}}`；补充查询：`{{query_or_none}}`。

## ReAct被拒候选补查

你负责根据下方失败画像候选的补查请求，重新搜索和读取能够直接验证这些候选的证据。
只处理请求中的候选，不生成新的画像范围，不修改已经通过的事实。优先使用候选给出的关键词、章节和相邻表格位置；找不到直接证据时明确结束，不得用相似表述替代原文。
补查请求：`{{recovery_requests_json}}`。
调用上限：模型 `{{max_model_calls}}` 次，搜索 `{{max_search_calls}}` 次，读取 `{{max_read_calls}}` 次，累计正文 `{{max_read_units}}` 条。

## 结构化事实抽取

你负责从给定 EvidenceUnit 正文生成科技型企业画像候选，不负责写企业短评、比较卡、风险评分或审批结论。
只输出合法 JSON 对象：`profile_items`、`profile_relations`、`information_gaps`、`conflicts`、`unmapped_items`。只抽取当前调查领域，不得顺便补充其他领域的画像项、关系或信息缺口。
每个事实和关系必须引用输入中真实存在的 `evidence_unit_id`，摘录必须逐字连续复制原文，不得改写、拼接、省略或用省略号代替。表格事实同时引用表头/口径和数据行；多年度事实保留每一年的报告期和统计口径。
企业陈述、外部支持、权威认定、已发生结果和风险提示必须区分；未确定内容只能写入信息缺口或冲突，不得猜测。
只抽取当前领域，不能把同一证据中其他领域的事实顺便写入。

`profile_items` 必须包含 `item_id`、`subject`、`section_id`、`field_id`、`value`、`value_type`、`information_status`、`content_role`、`evidence_unit_ids`、`evidence_quotes`；可补充 `unit`、`value_scope`、`reporting_period`、`event_date`、`source_date`。
`extraction_method` 只能使用 `llm`、`rule`、`import` 或 `manual`；本次 DeepSeek 结构化事实抽取统一填写 `llm`，不要输出 `direct_extraction` 等自定义值。
`profile_relations` 必须包含 `relation_id`、`relation_type`、`source_id`、`source_type`、`target_id`、`target_type`、`information_status`、`content_role`、`evidence_unit_ids`、`evidence_quotes`。
`field_id`、`section_id`、`value_type`、枚举、关系类型和证据 ID 只能从 Python 注入的白名单复制。`enterprise.legal_name` 必须使用原文完整法定名称，不能用“公司”“本公司”等代词。
`integer` 必须是非负 JSON 整数；`money` 的数值与单位分开保存；`ratio` 使用 0 至 1 小数；申请、授权、存量、新增量及统计截止日期不得混用。
同一对象、同一字段、同一期间和同一口径的重复事实只保留一项并合并证据；不同对象或不同期间不能合并。
所有 `information_gaps` 和 `conflicts` 只能描述当前领域，并以当前领域 ID 开头。不得输出比较关键词、相似案例或审批判断。

## 关系核验

你只负责核验失败的企业画像关系候选。只输出 `{"relation_decisions": []}`。
只处理给定请求中的关系。不得生成 `profile_items`、`profile_relations`、`information_gaps` 或其他关系。每项只填写 `candidate_id`、`supported`、`evidence_unit_ids`、`evidence_quotes`，不得生成新的画像项或关系。
判断关系谓词在原文中的语法作用范围：只有目标对象被关系谓词直接作用，或明确属于该谓词统领的并列/列举范围时，`supported` 才能为 true；仅共现或无法确定作用范围时必须为 false。
引用必须逐字连续复制输入 EvidenceUnit 原文。

## 输出修复

上一版输出未通过 Python 校验：`{{validation_error}}`。
只根据同一批输入重新输出完整合法 JSON；不得增加事实、关系、证据或信息缺口。所有 ID、字段和枚举只能从输入允许列表复制。
